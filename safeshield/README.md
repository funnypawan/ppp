# SafeShield – Adult Content Blocker

A native Java Android app for **the device owner's own digital self-control**. Android 8.0+ (API 26), compile/target API 35, Android Gradle Plugin 8.9.2, Gradle 8.11.1, JDK 17. No runtime third-party SDKs, advertising, analytics, accounts, root, accessibility surveillance, or TLS interception.

**Release status: debug APK built; not certified production-ready.** Core tests and the full Gradle debug APK build passed on GitHub Actions (run 39549519942). [Download the debug APK](https://github.com/funnypawan/ppp/releases/download/safeshield-debug-2/SafeShield-debug.apk). Android device tests and lint remain pending. Do not distribute as validated protection until the release gates in [TESTING.md](TESTING.md) pass.

## Open, build and install

1. Open **this `safeshield/` directory**, not the repository root, in Android Studio Meerkat or newer compatible with AGP 8.9.2.
2. Install Android SDK Platform 35 and Build Tools 35.0.0 with SDK Manager; accept licenses. Choose **JDK 17** as Gradle JDK.
3. Let Android Studio create `local.properties` with `sdk.dir`, or set `ANDROID_HOME`. Never commit local paths or signing keys.
4. On a machine with access to Google's Maven/SDK servers, Maven Central, and Gradle distributions:

```sh
cd safeshield
./gradlew :app:assembleDebug :app:lintDebug
# Windows: gradlew.bat :app:assembleDebug :app:lintDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

A Gradle wrapper, including its JAR, is included. The debug key is generated by the Android tools and is **not** suitable for release. A GitHub Actions workflow at `../.github/workflows/safeshield-android.yml` builds and uploads a debug APK when run; it successfully built and published debug build 2 during this session.

5. Open SafeShield, read the disclosure, enable protection and accept Android's VPN dialog. Notification permission is optional on Android 13+. Update the list; the offline seed is deliberately small. Automatic daily downloads are opt-in and can use mobile data.
6. For testing, turn off browser secure DNS and Android Private DNS **only if you knowingly accept their privacy trade-offs**. SafeShield does not change these system settings.

## Release APK / AAB

Use Android Studio **Build → Generate Signed App Bundle / APK**. Choose APK (sideloading) or Android App Bundle (Play), create or select your own protected keystore, select `release`, and keep key passwords out of source control. Back up your key securely. Increment `versionCode` for updates.

For command-line signing:

```sh
./gradlew :app:assembleRelease
# Creates app/build/outputs/apk/release/app-release-unsigned.apk
# Use build-tools/35.0.0 from your SDK; put your keystore OUTSIDE this repository.
zipalign -p -f 4 app/build/outputs/apk/release/app-release-unsigned.apk aligned.apk
apksigner sign --ks /secure/path/safeshield-release.jks --ks-key-alias safeshield \
  --out safeshield-release.apk aligned.apk
apksigner verify --verbose --print-certs safeshield-release.apk
```

`apksigner` prompts for your secrets; do not embed them in Gradle or shell history. Before publication, complete device tests, a security review, current target-SDK checks (target requirements change), Google Play VpnService and foreground `specialUse` declarations/review, Data safety disclosures and a publicly hosted privacy policy with the distributor's contact details. The in-app policy is provided, but a store listing/contact cannot be invented for you.

## What is implemented

- Native responsive dashboard, activity, settings, list details, Safe Search, PIN, privacy and troubleshooting screens. Large touch targets, scrollable content, system bars/insets, and PIN-window screenshot protection.
- `VpnService`: only `10.111.0.2/32`, the assigned virtual DNS resolver, is routed into a local TUN. IPv4 UDP DNS packets are validated, domain suffixes matched locally, and blocked requests receive NXDOMAIN. Two resolver workers, bounded queue, bounded cache, idle poll rather than busy-loop.
- Allowed DNS requests use HTTPS to **Cloudflare for Families** (`family.cloudflare-dns.com/dns-query`), including its adult/malware filtering. The provider sees allowed queries and your public IP. Only this app's own resolver/update traffic is excluded from the VPN to avoid bootstrap recursion.
- TLS uses platform certificate/hostname validation. No user-installed CA, traffic decryption, or custom trust-all code. There is no ordinary-plaintext DNS fallback for filtered queries.
- Replies validated for transaction ID and question. Cache maximum 256 entries, capped at 60 seconds and upstream TTL, with aged TTLs; no negative answer caching. Cache cleared on network changes, settings changes and list updates.
- Three consecutive resolver query/transport failures release the VPN (fail-open), preserving normal connectivity **unless Android lockdown blocks it**. Some DNS queries fail before release. A status message requires manual restart; system Always-on may restart according to Android policy. No promise of uninterrupted connectivity.
- Cloudflare zero-address answers are logged as provider filtering indicators, not proof of sexual content. Ordinary NXDOMAIN is not treated as a provider block.
- Local encrypted history (latest 200 requests + cumulative count), date/time and clear action. Counter means requests, not unique websites. Batched writes may lose the most recent two seconds on process death.
- Android Keystore AES-GCM preferences, no backup, salted PBKDF2-HMAC-SHA256 PIN hashing (210,000 iterations), timing-safe comparison, retry delays. Encrypted data corruption does not silently clear the PIN.
- PIN verification for settings changes, updates, pausing and history access once a PIN is configured. Strict mode requires a PIN. Neither defeats the device owner, uninstall, force-stop or clearing data. No recovery backdoor.
- Validated, bounded HTTPS blocklist updates and atomic replacement; previous list retained if download/validation fails. Opt-in persisted daily JobScheduler updates, subject to battery/network/OS scheduling. Source is StevenBlack's unified hosts + porn extension (also ads/tracking/malware, not only adult domains).
- Google `google.com` and `www.google.com` can use the officially documented `forcesafesearch.google.com` IPv4 address `216.239.38.120`. Other RR types return NODATA for these two names while enabled. Regional domains are **not** mapped. UI links to Google's own settings and YouTube's official Restricted Mode instructions; no unsupported account-setting APIs.
- Optional generic block notifications (no domain on lock screen), foreground status notification, boot status-check reminder and documented Always-on setup.

## Explicit boundaries

This is a **DNS-only, split-route VPN**, not a general-purpose IP firewall or full VPN client. It handles single-question, Internet-class, unfragmented IPv4 UDP DNS. TCP DNS and arbitrary IPv6 resolver traffic are not intercepted. The virtual resolver is IPv4, but AAAA lookups work through UDP and normal IPv6 website traffic remains outside the tunnel. Very large/truncated responses are not supported. Alternative/custom/encrypted DNS, proxies, other VPNs, direct IPs, cached connections and malicious apps can bypass filtering. Some DNS failure modes temporarily degrade access.

Do **not** enable Android **“Block connections without VPN”** with this split-route design: normal non-DNS traffic is not carried through the tunnel and lockdown can block it. Always-on without lockdown can be used for system-managed restarts, but needs device-specific verification. Only one Android VPN can be active. The app does not auto-launch a foreground service from the boot broadcast; Android manages Always-on and a notification otherwise invites the user to check protection.

DNS filtering blocks whole domains, including HTTPS domains and links from other apps that use system DNS. It cannot decide whether an individual video, picture or page on a general site is explicit. **Browser filtering** would require supported browser integration; none is implemented. **Image recognition** would require a trained, tested content classifier; none is implemented. No perfect-filtering claim is made. HTTPS block pages cannot be shown without interception; SafeShield uses ordinary DNS failure plus optional notification/history instead.

For stronger authorized enforcement, use supported Family Link controls or a properly provisioned Android Enterprise DPC. This app does not implement device-owner provisioning or claim to prevent uninstall.
